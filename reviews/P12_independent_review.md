## 3. P12 原始任务及实际职责

1. **实际职责。** 对同一 Skill、同一环境 E 的两份 P04 图、各自 P05 索引和分析者提供的有限契约，做单元划分、允许对应和有限观察比较。
2. **科学或工程问题。** 角色键相等且观察表可证时，哪些出现能够在版本之间保持身份；证据不足时如何放弃对应，而不是做最大匹配。
3. **输入。** `align(before, after)`。每侧含 `graph`、`index`、`contract`。CLI 为 `python -m dcfa.alignment before.json after.json`。
4. **正式定义。** 设计文档加上算法规范第 3 节：角色键五元组、出现至多参加一个配对、稳定绑定在约束相容时必须采用、局部唯一本身不是持续契约、两侧封闭且没有剩余候选才确认增删、观察未知与空表不同。规范写明两篇原论文都没有定义这组配对。
5. **核心算法。** 校验图摘要与范围；按契约划分互不重叠单元，未点名的 operation/effect 成为无证书单元；两两剔除角色、锚点和槽签名冲突；固定相同锚点；只在双侧封闭、角色完全已知、角色属于持续清单且双向度数为 1 时确认其余对应；对其余候选弃判；然后比较四列观察表和其中的上下文、安全剖面投影。
6. **类别。** 本项目原创的契约条件匹配。不是 KnotScryer 复现，不是 RogueOne 域对差分，也不是 P10 基线的扩展。
7. **与 P11 的接口。** 实现的是规范第 3 节的有限、可弃判片段。第 4 节的策略自动机、第 5 节的违规上下文差分和最小充分编辑集都没有实现。规范第 56 行仍写着算法尚未实现、P12 等待审核；这句对第 4、5 节仍然成立，对已经写在工作区里的第 3 节实现则已过时。
8. **P13 将得到什么。** 没有 P13 文件，不能规定它必须消费什么。当前实现能提供的是 `aligned`、`preserved`、`modified`、`added`、`deleted`、`unresolved` 和两侧证据。这些不是风险状态，也不是因果归因。
9. **原始验收标准。** 设计列出的事前性质：受契约支持的改名、移动和改写保持身份与两类等价；非安全输出变化只改变完整语义；安全剖面变化改变两类投影；重复角色保持歧义且顺序无关；单侧缺覆盖不报增删；显式聚合可反向比较；无契约的文本近似不能证明对应。

## 5. 核心算法正确性

对应关系是：同一技能的身份与观察是否可证 → 可信契约，而不是攻击者控制的 Skill 文本 → 规范第 3 节的部分配对 → 设计中的八步 → 单元字典、候选集合和观察行集合 → `prepare` 与 `align` → 本节所列探针。

在这个有限契约内，实现与设计一致。相同锚点在约束冲突时整次失败，而不是挑选一个候选。持续角色匹配只收取双向度数为 1 的边。因为相容关系是对称的，这类边互不相交，一次扫描就是该规则的全部不动点；它故意不解决“左侧唯一、右侧不唯一”的匹配。探针中 L1 同时相容于 R1 与 R2，L2 与 R3 双向唯一：只有 L2–R3 进入 `aligned`，L1 的两个候选都保留。

节点编号不参与对应。旧图的 `/scs/operations/0` 是 `check`，新图的同一编号是 `send`。在探针写入 `kind:label` 锚点和按标签区分的角色后，对应的是旧 `/scs/operations/1` 与新 `/scs/operations/0`，旧的 `check` 进入 `deleted`。这不是编号差分。

以下边界是定义的一部分，不是实现偏离：

- 角色、锚点、观察表和覆盖证书都由分析者提供。代码不从函数名或指令文本推导它们。
- 安全投影忽略输入列和输出列。只改变输入时，完整语义为 different，安全投影为 equal。
- 未绑定的合格节点使用全空角色，并与任何单元相容。它会阻断确定对应和增删。这是保守弃判。
- 组合证书不检查成员之间的真实控制或数据依赖。

`prepare` 在证据不是 verified 时丢弃锚点、角色和观察表。结果是未知，不是错误的确定对应。

## 9. 跨版本映射及风险差分

映射规则就是第 5 节的契约匹配。它没有绕回文件路径或节点编号。相同编号、不同角色被判定为一删一增；不同编号、同一持续角色被判定为保持。

风险状态差分不适用。输出没有 NEW_RISK、既有风险、缓解或不可比较环境。`security.state` 只表示观察投影的集合是否相等。探针里的授权剖面从 `profile` 改成 `other-profile` 后，投影为 different，同时没有产生策略标签。

P10 的域对结果没有进入本模块。

## 10. 修改证据真实性

不适用修改归因。对齐证据引用的是每一侧 P05 见证和图摘要。真实提取链中的见证带有路径、摘要、行号和片段，因为索引由 `build_index` 刚生成。对齐函数不重新打开 Skill 文件核对见证摘要；篡改后的索引只要图摘要仍匹配，就会被原样收录。设计要求信任索引生产者，这个界限在报告第 7 行有写。

## 11. 直接与间接归因

不适用。没有依赖传播。风险节点是否被修改，不是本模块的问题。

探针用合成脚本做了范围核对：旧版含 `check(token)` 与 `if allowed: send(item)`，新版只剩 `send(item)`。`if allowed` 没有成为图单元。两边契约都写 `authorized` 时，`send` 的安全投影为 equal。被删的是契约角色为 `check` 的调用单元，不是对守卫删除的因果结论。

## 12. 多修改共同影响

不适用。多个未决候选会同时保留。实现不选择唯一原因，也没有最小充分编辑集。

## 13. 无关修改及伪归因

不适用伪归因器。与对齐有关的负面结果是：同一文件中的第二个同角色单元会使持续角色失去双向唯一性，从而不配对。仅仅位于同一文件不会建立对应。

未改契约表时，源码变化不会单独改变安全投影。这能防止把无关文本变化当成安全投影变化，也说明本模块看不到契约没有编码的变化。

## 14. 删除型修改归因

不适用。封闭世界下，没有剩余候选的已知角色会进入 `deleted` 或 `added`。这表示该契约单元没有对应者，不表示保护机制被证明删除。第 11 节的 `check` 单元进入 `deleted`，而 `send` 的授权投影保持不变。

## 15. 相关性与因果关系

本阶段最多支持到：契约声明的单元在约束下对应，且两张有限表不同。由此不能推出源码中的某一行导致了风险，也不能推出更新具有恶意意图。报告第 50 行把实验结果限制在给定契约的对齐规则上，这个限制与代码一致。

## 16. 配对验证

不适用运行时配对。两个版本只作为静态 JSON 读入。CLI 不执行 Skill 脚本。审查使用的 Python 片段也只进入 `extract` 的静态解析。

## 17. 原始证据完整性

确定对应和增删都保留成员编号、证书、角色、观察行、图摘要、环境、作用域和见证列表。未决项保留侧别、成员、候选和粗原因 `ambiguous_or_unproved` 或 `insufficient_coverage_or_role`。

空观察表与缺表不会被混成同一种结果。另一版本的节点编号不会被当成本版本见证。

P12-N02 使返回值中的见证字典和 `slot_evidence` 列表与调用者原对象共享。就地修改返回值会改到索引或契约，从而影响下一次调用的证据文本。单次调用内部没有跨版本串写。

## 18. 前置模块累计误差

适用链路是 P03 提取、P04 建图、P05 索引，然后 P12。项目测试和探针都走了这条链路。P06 的跨语句与条件缺口仍留在上游图里；P12 不把这些缺口补成已验证边。P08 至 P10 不在调用栈上，全量测试通过只能说明它们的既有测试仍可运行，不能说明它们的输出被 P12 正确消费。

索引若把一条 operand 边标成未验证，槽约束会消失，匹配变得更不确定，而不会凭空出现一条度数为 1 的新边。这个方向是保守的。

## 19. 科研创新独立性

已落实的新计算是：在外部有限契约下维护部分配对，用稳定锚点和双向唯一的持续角色确认对应，并在其余情况下保留多个解释。它不计算图同构，不估计匹配概率，也不把观察差异换成风险分数。

KnotScryer 提供单快照的能力描述，RogueOne 提供域对集合差分。二者都不提供这里的实体对应规则。当前代码没有把“调用这两种方法”本身当作创新。

该机制可以在小契约上独立复算。它还不能对未知 Skill 自动生成角色、覆盖证书和观察表，因此没有单独的消融实验可做。没有实验证明它优于冻结基线。

## 20. 科研科学性

实现没有读取 `evaluation.ndjson`，没有按样本名写规则，也没有把 P10 候选写成 ground truth。测试使用固定合成角色，这是契约夹具，不是评价集调参。

报告没有把静态对应写成因果证明。设计中的事前性质均带有“受契约支持”或“封闭覆盖”的前提。规范第 56 行的状态句尚未同步，见建议 P12-S01。

## 21. 软件工程质量

模块边界清楚：纯函数、无全局缓存、不导入差分基线。主要代价是两侧单元数的乘积，另加每单元的槽数；没有指数枚举。CLI 把预期内的输入和契约错误收成退出码 2，同时也会把索引结构错误收成同一出口。调用方必须看 `reason`，不能只看退出码区分摘要错误和锚点冲突。

返回值别名是具体的接口缺陷。类型检查 NOT_RUN。没有搜索状态爆炸，因为本算法不展开路径。

## 22. 现有测试有效性

`tests/unit/test_alignment.py` 的 8 项测试真实调用提取、建图和索引，并检查了保持、两种投影、歧义与顺序、聚合、覆盖证书、缺表、锚点冲突和交叉槽。它们能够证明：测试所写的契约会被忠实执行，改写后的指令文本不会被自动阅读。

它们不能证明：

- 一对一但没有持续契约时必须放弃对应；
- 一个未绑定节点会阻断确定匹配；
- 只修改输入列不改变安全投影；
- 槽配对使用了实参表达式。交叉测试把 `neighbor_binding` 写成 `first-input` 与 `second-input`，实现比较的是这个字符串。

`assert unresolved` 只要求列表非空。报告第 46 行“按不同 operand 槽的来源交叉配对”应理解为契约绑定，不应理解为读取了实参源码。
