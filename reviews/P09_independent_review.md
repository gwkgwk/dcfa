## 3. P09 原始任务及实际职责

没有独立任务书。下列职责全部来自 `docs/P09-design.md` 第 3–7 行，并与 `src/dcfa/trust_diff.py` 对照。

P09 解决的是工程比较问题：在 P08 已经给出的 owns 与 may data_flow 上，计算两个入口快照的有向域对集合，再做集合差分。科学上它只复用 RogueOne 的域流定义和集合差，并明确拒绝论文 §4.4 的 benign/rogue 判决。

输入是调用方保证为同一 Skill、同一 P08 配置、同一逻辑入口的两份快照。P08 JSON 没有 Skill 身份或配置签名，P09 不补写该身份。输出是两侧各自的流、见证和导入假设，以及 `added`、`deleted`、`retained`、`unresolved_before`、`unresolved_after`、`alerts` 和总状态。

形式定义：

- `R(t)` 是域 `t` 的根。闭包包含根自身。
- 对 `a ≠ b`，当且仅当 `Reach(D, R(a)) ∩ Reach(O, R(b))` 非空时记录有向对 `(a, b)`。
- 根只来自 P08 支持的三类：`literal → :local`；`kind=api`、`name=open` 且 `domain=file` → `builtin:file`；`kind=module` → `import:<name>`，解析值只能是 `stdlib_name_unverified` 或 `unverified_external`。
- 其他节点只通过闭包获得归属。`domain` 字符串不是根，也不是归属证明。
- 没有调用方对象，不构造 `:caller`。
- 域对相等不使用节点编号、行号或调用次数。每对保留一个存在性见证：一个共同对象，以及本侧边上的两条根到该对象的路径。
- 新增对在旧侧可比较且 `complete_in_subset` 时进入 `added`，并产生 `new_possible_cross_domain_flow`。删除对要求新侧完整。损坏输入、入口不同、解释未完成保留未知原因。正见证可以保留。

类别是 **必要适配**，不是 DCFA 原创算法，不是忠实的全论文复现，也不是对比基线的削弱版。§4.3 跨包 dead-end 消除被报告明确排除，不记为缺项。

## 5. 核心算法正确性

对应关系如下。

| 环节 | 内容 |
|---|---|
| 科学问题 | 同一入口的两个 P08 图，跨域 may 流集合是否变化 |
| 威胁模型 | 不新设。沿用“旧版是比较参考”的论文假设，但只产出候选，不产出 rogue |
| 数学定义 | 设计第 3–5 行的根、有向闭包、交集和集合差 |
| 算法 | 校验快照；识别三类根；分别做 owns 与 data_flow BFS；记录相交对；按完整性门控差分 |
| 数据结构 | 本侧节点表、按边种类的邻接下标、父指针、每对一条 flow |
| 实现 | `extract` 与 `compare` |
| 验证 | 不导入 `closure` 的集合参照，加上从目录经 `analyze` 到 `compare` 的样本 |

实现与定义一致的部分：

- BFS 从排序后的根出发，已访问节点不入队，环会终止。父指针指向发现该节点的边，回溯得到一条从根到共同对象的路径。
- 自流被 `source != dest` 排除。`import a, b; a.emit('x'); b.emit('y')` 得到 `(:local, import:a)` 与 `(:local, import:b)`，没有 `(import:a, import:b)`。无实参的 `a.read(); b.read()` 得到空流。
- 报告示例与单测预期一致：保留 `(:local, import:first)`，新增 `(:local, import:second)` 和 `(import:first, import:second)`。倒序后这两对进入 `deleted`，告警为空。
- `open('p')` 到 `net.send(open('p').read())` 保留 `(:local, builtin:file)`，新增 `(:local, import:net)` 与 `(builtin:file, import:net)`。没有反向的 `(builtin:file, :local)` 误报。临时目录中没有被创建的 `p`。
- `a='no'; api.emit('yes')` 的数据流见证根是 `'yes'`。未连接的字面量没有被拿来充见证。
- 跨文件样本中，`(:local, import:api)` 的数据流末边位于 `helper.py` 第 3 行，即 `api.emit(x)`。
- 状态门控与设计一致。旧侧停在 `if` 时，新侧 `open` 进入 `unresolved_after`，没有告警。新侧在已有流之后停在 `if` 时，旧流保留，不标删除。只出现在未解释分支里的导入不产生流。坏引用、`bool` 行号、`bool` 节点号、缺少 `resolution` 的模块都使该侧 `invalid`，不产生告警。

已核对、但不是算法错误的行为：

- 旧侧完整、新侧 partial，且 partial 图里已经有一条旧侧没有的流时，`added` 和 `alerts` 非空，总状态是 `unknown_or_partial`。设计允许在另一侧完整时保留正见证。CLI 仍返回 1。
- `import api` 与 `import api as sink`、以及把 `emit` 改成 `exfiltrate`，域对都不变。字面量从 1 改为 2 也不产生流。这是“一个 :local、按域对而不是按成员相等”的直接结果。
- 新增但未参与跨域流的导入只出现在 `import_assumptions`，不出现在 `alerts`。
- 入口字符串不同时，相等的流进入 `unresolved_before`，`added`、`deleted`、`retained` 都为空。空集合在这里表示不可比，不表示没有流。

适用范围就是设计写明的显式入口和 P08 可能流。局限是：域内成员、参数字面量和未使用导入的变化不可见；见证不唯一；论文的跨包 dead-end 未做；没有 Skill 身份核验。这些都已在设计或报告中有边界，报告对域内不可见性的表述仍然偏弱，见 S01。

## 8. 能力流图专项分析

P09 不建图。它消费 P08 的节点和两类边。

节点身份沿用 P08 整数 `id`，类型限于 `module`、`api`、`function`、`literal`、`result`、`file_handle`。重复 `id`、缺文件、非正行号会拒绝整侧。模块根还要求名字是标识符、`domain` 与 `import:<name>` 一致、解析值属于两个未核验字符串之一。

边必须是 `owns` 或 `data_flow`，两端都指向本侧节点。P09 不补边，也不把共现提升为流。独立探针里两个模块分别接收不同字面量，没有产生模块到模块的对。

图上的可达是 P08 的 may 关系。P09 的见证表示静态闭包里存在一条边序列，不表示该序列在运行时一定会执行，也不表示攻击成功。环由访问集终止，不会把环展开成无限路径。

## 9. 跨版本语义对齐专项分析

不适用。P09 没有对齐器、相似度、阈值或一对一匹配。

因此下列变化不会被识别为“同一实体的修改”：

- 模块改名会表现为一个导入域删除、另一个导入域新增。
- 文件移动若改变 P08 的 `entry` 字符串，整次比较不可比，而不是把能力迁到新路径。
- 同一导入域上的成员改名、参数字面量变化，域对保持不变。

这是本阶段的定义边界。P10 不能把这种空差分读成行为等价，也不能把域对的删除加新增读成已经完成语义对齐。

## 10. 图差分与风险状态分析

P09 做的是域对集合差分，不是文件差分、文本差分、节点差分或策略状态差分。

| 变化 | 实际结果 |
|---|---|
| 新的跨域相交 | 旧侧完整且入口相同则 `added`，并有一条候选告警 |
| 旧的跨域相交消失 | 新侧完整则 `deleted`，无告警 |
| 两侧都有同一对 | `retained` |
| 入口不同或对侧不完整 | 该侧候选进入 `unresolved_*`，不叫新增或删除 |
| 只改域内成员或本地字面量 | 四类集合都不表示这次变化 |
| 图结构损坏 | 该侧 `invalid`，不参与正例差分 |

没有安全、违规、增强、缓解这组状态。告警数量不是严重性。既有域对继续存在时不会被报成新风险。新增域对只是候选流，不是已经证实的违规。

## 11. 路径搜索及风险归因分析

不适用策略搜索和因果归因。

见证搜索是父指针回溯，不是带权限、条件或信任边界约束的策略路径搜索。没有深度、长度或候选数上限；环由访问集终止。达到资源限制这一状态不存在，因此也不存在把截断写成“无风险”的分支。

见证把一个共同对象连到两侧根和源码位置。这是静态证据关联。它不证明该修改导致了风险，也不证明旧版没有其他未建模行为。多处编辑可以同时体现在多条域对上，实现不做主因选择。

## 12. 证据完整性

每条 flow 含域对、共同对象编号、两条路径的根和边下标。边下标只解释本侧 `edges`。节点再查本侧 `nodes`。文件和行号来自 P08。告警只保存域对、固定理由和 `evidence_version=after`，详细路径要回查 `after.flows`。未核验导入在 `import_assumptions`，不复制进每条告警。

CLI 的 `input_sha256` 是成功读到的 JSON 字节的 SHA-256。缺文件没有该侧哈希。报告已说明它不能代替 Skill 源哈希。

没有发现虚构文件、把旧侧行号写进新侧、或把模型推断写成事实。Skill 正文中的 “Ignore previous instructions.” 没有进入比较结果。

进程内返回值与输入共享 `nodes`、`edges` 和 `issues` 列表。CLI 先序列化，不受调用方事后修改影响。见 P09-N01。

## 13. 前置模块累计误差

P09 不导入 `program_flow`。测试和审查的端到端样本调用了当前工作区的 `analyze`。该文件哈希与 P08 终审一致，本次没有改 P08。

已核对的传递：

- 第一检索同时给出的 owns 与 data_flow 被闭包使用，没有被 P09 改写成 domain 成员资格。
- 模块根的 `resolution` 进入 `import_assumptions`，两条允许值之外会使整侧无效。
- `unvisited_functions` 原样保留。未进入函数体里的导入不会变成流。
- `complete_in_subset` 只被当作“入口解释完成”的门控，没有被解释成跨域闭包已经由 P08 算完。
- 旧侧或新侧的 partial、invalid 不会被收成空告警加安全结论。

P08 若漏边或误加边，P09 会沿这些边计算。这是前置误差的传播，不是 P09 另写了一套图。审查没有发现 P09 用临时补丁掩盖 P08 的边定义。

## 14. 科研科学性

算法来自定义好的域流交集和集合差，不来自评价集里的攻击字符串。实现没有样本名、路径或标签分支。本次没有读取冻结评价集，也没有按检测结果改阈值。

报告没有把候选流写成恶意，没有把空差分写成无害，没有估计检测性能，没有把 dead-end 排除说成论文结论。它正确停止在 P09。

报告第 9 行把“节点重排”和“图环”列入项目测试已经验证的项目。单测第 58–59 行添加的是第一条 open 边的自环；别名测试换的是另一段程序，不是同一节点数组的置换。审查探针另行证实了真环和反转后的域对稳定性，所以算法结论成立，但这句测试覆盖描述过宽。见 P09-N03。

当前证据能支持的结论是：在 P08 子集上，域对差分和完整性门控按设计工作。它不能支持“一般程序语义等价已解决”，也不能支持“新增域对就是恶意更新”。

## 15. 软件工程质量

`trust_diff.py` 职责清楚：`extract` 校验并求流，`compare` 做门控差分，`main` 只负责两份 JSON。无循环依赖，无配置文件，无网络。异常变成该侧状态或 CLI 的 `issues`，不吞掉后返回空成功。

时间开销是按域的 BFS 加上可达对象上的拥有者枚举。空间保存两侧原图和每对一条见证。没有另外的候选组合爆炸。大规模行为 NOT_RUN。

可维护性良好。后续阶段应把本模块当域对差分，而不是当对齐或裁决器。进程内别名是唯一直接的接口卫生问题。

## 16. 现有测试有效性

`tests/unit/test_trust_diff.py` 有 4 个测试函数；CLI 参数化后是 6 个用例。预期由手写断言给出，语义用例经过真实 `analyze`，没有 mock 闭包。

这些测试能够证明：

- 报告中的 first/second 示例得到预定的新增、保持和告警，见证沿本侧边走通，且文件在该样本中是 `main.py`。
- 倒序比较把新增变成删除且不告警。
- 导入别名和重复调用保持同一域对。

这些测试不能证明：

- domain 标签或名为 open 但域不是 file 的 API 不会成为根。
- 同一张图的节点、边置换不改变域对。
