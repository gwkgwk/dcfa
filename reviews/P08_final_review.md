## 2. P08 原始任务与验收标准

原始任务没有改变：一次单快照、一个显式 Python 入口、有界静态读取、程序级 JSON，不消费 SCS，不做跨版本比较或策略判断。

## 6. 能力流图专项复核

节点编号仍是一次分析内的下标。同文方法在不同父对象上不会合并：`left.emit` 和 `right.emit` 是两个 api 节点，实参可达集不相交。同一父对象上的同名成员会合并，这是修订定义要求的复用，不是错误合并。

owns 与 data-flow 同时存在于首次检索和外部调用。方向仍从已有对象指向新建对象。文件句柄到 `read` 结果有直接 data-flow，因为句柄被当作绑定方法的实参。模块对象没有这条隐式实参边；模块之所以能到达调用结果，只是因为“根到成员”再加上“成员到结果”的传递，这与 §4.2(2)(4) 的边一致。

没有条件边、权限边或策略路径。`if` 不制造恒真流。两个独立调用的字面量可达集不相交，共现没有变成互流。循环不会留下回边：自名引用和活动对象再调用都会停止。

不确定性现在有三处机器可读记录：`issues`、`resolution`、`unvisited_functions`。成员节点本身没有 `resolution`，要沿 owns 回到模块根才能看到。这与“标记写在导入根上”的定义一致。`domain` 仍然不能单独当作信任域闭包。

§4.3 的 owns 可达集和 data-flow 可达集没有作为结果计算。图里有可供以后计算的边，但输出本身不是跨域流集合。
