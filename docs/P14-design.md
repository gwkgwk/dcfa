# P14 单键有限上下文差分设计

依据 P11 algorithm_spec §5。compare(before,after,mapping,contexts) 一次处理一个能力单元的一个策略键。每侧包含 graph、members（缺席为空）、reports（P13 原始结果列表）、key（策略、主体、资源、动作）、configuration（可信调用方固定的策略版本、环境、工具、分析预算及精度配置标识）。contexts 是调用方预先声明的完整互斥 (purpose,invocation) 有限集合。角色通过共同环境中的稳定语义名绑定；P12 对应是唯一允许的能力身份依据。分析者须保证每份 P13 覆盖证书针对所指定单元；有路径时还核查效果端点。不同键应分别调用并保留独立记录。

对 L1,U1,L2,U2 逐上下文计算新增、移除、共同违规的界。对每一允许布尔补全记录是否出现 old-only、new-only、both 三个区域，再合并下一上下文；最多八个状态。按 P11 整键表分类，可行标签不唯一返回 unknown。加剧要求旧集非空且严格包含于新集；缓解取反向。完整证据同时记录保持满足和持续违规。相同快照、相同契约结果、相同单元和配置可用恒等解释；非同快照的 P12 角色对应不构成观察等价证明。时间随所给证据和上下文数线性增长（输出排序另计）。输入包含可信生产者的原始输出，不鉴别其数字签名。

缺测保持上下界 [0,1]，未适用单列；适用性变化、配置或对应不一致标不可比较。P12 确认增删时单列单侧状态，不从结构变化推断另一版违规。输出保存两侧快照摘要、语义对应依据、原报告、候选和见证；不归因修改。

执行前预期：相同的未知快照零变化但保持状态未知；改名且确定投影相同则保持；空到非空引入；非空真包含为加剧；反向为缓解；非空到空解除；两方向均改变为混合；未知变违规同时容许引入和保持；缺报告不能证明旧版安全。用独立集合枚举检验整键标签。

## 审查修复设计及阶段状态（S01–S04）

以本节更新 P11 规范末尾的历史进度记录：第 4 节的单上下文片段已在 P13 实现，第 5 节的有限上下文集合差分已在 P14 实现。修改归因仍待实现；冻结的数学定义沿用原版。

certainty 衡量两个布尔可能值集合大小的变化。二值集合变为单值是 increased，反向是 decreased，同大小是 unchanged。safe → violation 的风险状态改变但信息量相同。missing 与 unknown 均允许两个布尔值。

在域内先依据策略键检查动作适用性。动作已知不匹配且两侧均缺报告的上下文排除在集合运算外，保留 not_applicable；单侧已有不适用报告而另一侧缺测仍保留接口约定的 incomparable。普通适用键缺测继续使用双界。快照证书允许两侧独立使用 64 位 ASCII 十六进制的任意大小写；不合规或摘要不同不启用证书，其余图、角色与报告一致性要求照旧。
