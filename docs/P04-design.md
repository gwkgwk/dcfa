# P04 单 Skill 内部能力流图定义

## 原文复用判定

§III-B 提供带证据的能力事实。§III-C、图 4、算法 1 第 3–5 行支持单 Skill、输入／输出端口、操作、效果、上下文和信任边界节点，以及 reads、produces、transforms、exposes、sanitizes、crosses-boundary 内部关系词汇。原文第 4 行没有展开逐边恢复规则。P04 采用其中可用证据支持的子集；式 (1) 的跨 Skill 配对不适用。本阶段的方法身份为论文结构适配及内部关系恢复扩展。[论文 §III-C](https://arxiv.org/html/2610.32155v1#S3.SS3) · [P01 范围判定](reproduction/knotscryer_scope.md)

## 输入与形式化定义

输入为单个通过 P03 校验的 p03.2 快照 S，及可选的调用点绑定 B。B 是由分析者提供的独立静态说明，以 S 中操作索引定位，附被绑定的调用名称、工具标识和绑定依据。只能作为假设使用。分析器不访问 S 或 B 内引用的路径。输入须来自可信 P03 流程；校验结构无法认证伪造证据。

输出 G=(V,E,U)，V 为带类型、标签和证据指针的节点集合，E ⊆ V×R×V 为带规则及依据的有向边，U 为待确定的关系或分析缺口。图内嵌 S、B，指针锚定相应数组位置；P03 的文件位置、属性、原文片段和分值由指针保留。身份使用本次输入中的出现位置，同名数据与操作各自独立。单一 Skill 根节点通过 contains 连接其组成部分；此边仅表达归属。

| 实体或边 | 生成条件和语义 | 证据层级 |
|---|---|---|
| 指令、文档动作 | 每个 instruction_action 保留指令原文节点及动作节点，指令到动作的 describes 边表示 P03 的句式解释 | 可能 |
| 程序操作、数据对象 | 每个 call_expression 生成调用点；每个实参源码表达式按槽编号生成对象。点号调用另记录接收者表达式。对象到调用点的 operand 边表示语法操作数 | 静态语法事实；实际求值未知 |
| 工具调用 | 仅当显式 B 对应具体调用点且名称一致时，生成工具节点和 may_invoke 边；无 B 则记录绑定未知 | 条件推断 |
| 资源、效果、上下文、边界、端口 | 文件清单保留资源身份；其余按 SCS 主张各自建点。清单出现无法推出某个操作读取资源 | 记录事实；声明的行为待证 |
| reads、produces、exposes、crosses-boundary、may_cause | 将单条证据片段按 P03 原文法复核。仅当同一原文锚点下存在唯一匹配动作、对应角色及字段均与该句解析结果相等时连接。输入端口→动作；动作→输出端口／上下文／信任边界／效果 | 可能，含两端证据 |
| unknown | 无法归属的声明、未解析工具目标、未解释指令和 P03 诊断进入 U，无可遍历的猜测边 | 未知 |

程序操作数定义以 Python Call 的 callee、args、keywords 和 Attribute.value 的语法角色为依据。表达式出现不保证运行时绑定、可达性或对象别名。数据实体与操作分开建模也参考 PROV-DM 的实体／活动区分；这里只建模静态主张，未观测实际执行事件。静态条件不足时，转换、清洗、跨语句 def-use 和文件读写关联留为未知。[Python AST](https://docs.python.org/3.10/library/ast.html#ast.Call) · [PROV-DM](https://www.w3.org/TR/prov-dm/)

## 接口与验收

build_graph(S, B) 返回 p04.1 JSON 对象。validate_graph(G) 检查输入及由证据契约允许的完整投影；JSON 和 DOT 导出前均校验。dcfa graph SCS.json [--bindings FILE] [--format json|dot] 输出到 stdout。有效部分图仍可导出，SCS 状态保留；错误输入退出非零。DOT 以实线显示静态结构、虚线显示推断，展示未知项。采用合成夹具对照正反例：相同名称／类型、不同原文锚点不得产生数据流；工具无显式绑定不得推断；端点、依据、确定性或状态被篡改应拒绝。运行前置测试。

### 程序调用之间的局部值流

为检验程序操作之间的流，增加一个可证伪的局部规则。若同一单行表达式或语句的 AST 中调用 c 直接占据调用 p 的一个位置参数／关键字值槽 j，且该行全部调用按 P03 顺序、名称与实参源码能一一对应 SCS 调用记录，则加入 c → operand(p,j) 的 result_to_operand 可能边。依据是 Call.args / keyword.value 的父子关系及实参求值语义。此边以两端调用成功求值为条件。对分行、动态目标、不可重解析、数量或实参不符的行关闭此规则并记录未知。重复使用同名变量不会产生跨语句边。[Python 调用表达式](https://docs.python.org/3.10/reference/expressions.html#calls)
