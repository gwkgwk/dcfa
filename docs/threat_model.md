# P11 单 Skill 更新威胁模型

## 主体、资产与信任契约

分析者保护调用方的私有数据和对受保护资源的操作权。潜在不受信任的更新提供者能改变同一 Skill 的说明、代码、配置或资源，也可能只是开发者误改。外部内容可影响输入值，无法自行授予工具权限。执行者是读取说明并可能调用程序或工具的 Agent。平台、调用方确认的资源标识、授权记录和工具契约构成建模依据；Skill 自称“已授权”只是一条不可信文本。可信组件被攻陷、隐蔽通道、跨 Skill 编排和主机权限提升均超出范围。攻击者能力由可改动的制品及可达接口导出，未采用评价集的攻击类别。

形式上固定环境 $E=(S,R,T,B,C,Γ)$：主体、资源、工具、信任边界、允许的调用上下文集合、带来源的可信事实。上下文 c 指定调用方、数据分类、目标资源和当次授权。授权是对 (主体,动作,资源,目的,调用实例) 的关系；有效期或目的缺证时取未知。两版用相同 E、策略和分析预算，环境变化须另立比较。例：给“预览”工具授权不蕴含允许“发布”。可验证性质是改变无关资源的授权不会解除本资源的保护；前提是资源身份可区分。[KnotScryer §II-D、§III-B/D](https://arxiv.org/html/2610.32155v1) · [RogueOne §4.3](https://yinzhicao.org/RogueOne/RogueOne-ICSE24.PDF)

## 从安全属性到策略

这里先规定两项有限前缀可见的安全属性。事件带对象、来源、目的、时刻和生效门的证据。在同一条可行轨迹上匹配所有谓词；采用三值逻辑，未知授权不能作授权缺失。若契约显式封闭列出了全部有效授权，才可由查无记录推出否定。此设计借鉴安全性质的坏前缀判据及 KnotScryer 的效果、阻断条件；具体策略由本项目威胁模型定义。[Schneider, Enforceable Security Policies](https://www.cs.cornell.edu/fbs/publications/EnfSecPols.pdf) · [KnotScryer §III-D、表 I](https://arxiv.org/html/2610.32155v1#S3.SS4)

|属性与威胁|形式化坏事件或前缀|最小例与预期|性质及边界|
|---|---|---|---|
|保密性。更新可改变敏感数据的目的地或移除放行条件|存在 send(x,d)，x 有 private 来源且敏感性沿该路径保留，d 在许可边界外，并明确缺少对该次传递的有效放行|合成私有标记进入外部模拟端点，契约明确禁止，产生候选；public 值不触发本策略|未携带该来源的共现数据不能成为见证；经过可信、适用于该值和目的地的降密后重新判定。加密、改名或一句“已脱敏”本身不证实降密|
|操作完整性。更新可让不可信来源影响受保护写入|存在 write(r,v)，r 受保护且来自不可信输入的数据或有证据的控制依赖影响该写入，缺少覆盖本动作和资源的有效授权|不可信文本提供模板内容，显式绑定的工具将其写入受保护的模拟配置；授权仅覆盖另一资源，产生候选|写入独立常量且无控制依赖时不能仅凭同文件出现建立本策略见证。来源、绑定或执行门未知则保留未知|

授权声明、授权事实、检查是否实际约束每条通往效果的路径，是三个独立的问题。说明文本中的“先询问”不能证明程序入口强制执行该门。模型可以表达“Agent 遵从指令”的条件化路径；对 Agent 实际选择无观测时，报告只限于可能行为。两项策略不声称覆盖所有不安全行为。若增加策略，应先列明资产、可控输入、受保护的效果和可验证反例，再固定版本。

## 不安全与恶意

对具体执行模型 M，$Unsafe(V,c,π) ⇔ ∃τ∈Exec_M(V,c): Bad_π(τ)$。实际发生还须该次执行轨迹属于违规集合。恶意意图 $Intent(u)$ 是提交者 u 有意使更新服务于伤害或越权目的的命题；静态接口没有这个输出。误删授权检查和有意删除可产生完全相同的快照。性质：相同输入与环境应得相同状态，不因假想动机不同而改变；没有可信外部意图证据时，Intent 不可识别。安全更新判定还须指明策略、上下文及分析覆盖。[RogueOne §4.4、§6](https://yinzhicao.org/RogueOne/RogueOne-ICSE24.PDF) · [研究问题](research_problem.md)
