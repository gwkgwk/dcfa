# P15 单键风险变化与编辑证据关联设计

依据 P11 §5 的 Rel(d,w)。输入是同一 Skill 的两份完整、可信的内存文件清单（相对路径到 bytes）、各自的 P04 图与 P05 索引、P12 对应及 P14 单键差分。文件系统采集由调用方负责；本模块只读内存。用原始字节哈希与行序列重放编辑。缺文件只有在完整清单前提下才是删除。重命名保守表示为删除与新增。二进制或不能解码的修改保留两侧摘要。

按 P14 的新增及缓解区域（确定或可能）分别提取新旧对应上下文中的见证、排除与候选子图。固定两侧身份、键、端点、路径方向和 P05 引用；重放原件哈希及坐标。编辑 hunk 与节点/边/能力的验证来源行相交只产生位置关联。一个保守的语义规则：两个对应单成员调用的同一已绑定载荷槽，在两侧都是经 AST 重放的同一直接调用的常量位置参数，且类型或值改变，则该槽经 operand 边到效果的值前提改变。授权、守卫与可行性仍来自 P13 契约；此规则不证明值变化导致策略变化。其他结构变化可报告 AST 表示及位置关联。多个候选分别保留，按上下文和前缀归组。无独立反事实求值时，最小充分集、必要性和联合因果均未知。

预期：已绑定字面值变化得到依赖关联；只改注释得到位置关联；同文件无关行不关联；多处独立编辑共存；删除保留旧位置；错哈希不能作为证据；保持区域不产生风险修改归因；不确定变化保留上界。

## 审查修复设计与阶段进度

P15-M01：files.hunks 保留原始编辑。candidate_edits 仅索引这些编辑块。每一侧每个位置证据在 locations[].edits[] 中输出 matched_lines，取已重放见证区间与该版本 hunk 行区间的交集，闭区间、从 1 开始。edit_targets 中使用相同定义。真实见证和文件级 hunk 均原样保留。多个不连续位置分别报告。单行内仍无法从位置重叠确定具体表达式相关或建立因果。

P15-S01：截至本工作树，P13 实现 P11 §4 的单上下文求值，P14 实现 §5 的有限集合差分，P15 实现该节的有限位置关联和已绑定常量参数规则。最小充分编辑集尚未实现。
