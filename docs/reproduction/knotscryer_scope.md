# P01 审计设计与单 Skill 复现边界

## 问题与方法

P01 以一个固定版本的论文及能与作者建立关联的公开制品为输入，交付章节审计、源码映射状态、范围判定和来源清单。逐项区分原文明示、由算法推出和本项目需定义的部分。通过论文版本、PDF 摘要、算法行号及来源检索记录核查结论。源码缺失时保留空值。阶段仅做静态文献审计。

## 单 Skill 内部图究竟做到哪一步

**原文确实把每个 Skill 的内部端口级结构放入 SCFG。** §III-C 枚举内部关系；图 4 在两个 Skill 各自边界内画了内部连接；算法 1 第 3–5 行先逐 Skill 加入节点和边，第 11 行才要求候选输入来自另一个 Skill。因此可直接从伪代码推出：当输入集合只含一个 Skill 时，第一步仍成立，第二步没有符合条件的端口对。这是对论文算法的推论，尚无官方程序的单输入执行结果。[§III-C、图 4、算法 1](https://arxiv.org/html/2610.32155v1#S3.SS3)

**逐条恢复且可定位修改的内部能力流仍是适配扩展。** §III-B 把来源文件、片段、提取方法、置信度附在主张上；§III-C 算法 1 第 4 行把内部建图封装为一个操作。公开说明未给出各关系的完整端点约束、如何消解多个候选端口、语句或调用点的建边规则，也未展示针对单 Skill 内部边的独立真值评价。故原文支持端口级建模思想；其证据不足以确认可生成项目所需的、能从单条内部边追溯至具体修改位置的图。[§III-B](https://arxiv.org/html/2610.32155v1#S3.SS2) · [§III-C](https://arxiv.org/html/2610.32155v1#S3.SS3) · [§IV](https://arxiv.org/html/2610.32155v1#S4)

| 部分 | 单 Skill 决策 | 依据 |
|---|---|---|
| SCS 单位、六类信息、从声明与脚本搜集证据 | 可直接沿用论文概念；以后按论文方法重实现，具体提取规则单独说明 | §III-B，图 4 |
| 端口级内部节点和关系 | 沿用原文词汇与算法 1 第一步。逐边恢复、证据关联、歧义和未知的表达需项目设计 | §III-B/C，算法 1 第 3–5 行 |
| 控制、授权、清洗、来源 | 可沿用概念区分。单 Skill 中能否证实给定数据经过某项控制，需另做局部语义与合成测试 | §III-B/D，表 I |
| 跨 Skill 通道筛选及其生态搜索、链级双层验证 | 仅审计其边界；超出项目范围 | §III-C/E，式 (1)，算法 1 第二步、算法 2 |
| 版本间语义对齐、状态变化和修改归因 | 属于项目后续新问题，需另行定义与验证 | §II-C/D 研究运行时组合；§III-D 式 (2) 描述沿路径前进；§V 描述单次快照的外部效度 |

阶段依赖：人工审核本判定后，后续 SCS 工作可采用“论文方法重实现”身份。若后来发现官方源码，须先核对作者归属、许可证、完整提交和与论文版本的对应关系，再补做映射。外部测试集不能用于补齐提取规则。
