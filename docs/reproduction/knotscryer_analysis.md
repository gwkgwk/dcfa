## §I–II　研究问题与威胁模型

作者问的是多个单独通过审查的 Skill 在 Agent 编排下能否形成违反安全策略的组合。clean 的操作性依据来自既有扫描或市场标签。§II-B 用 Decision、Execution、Reasoning 描述一次调用；上一次推理结果影响下一次选择及输入（图 2）。§II-C 要求候选具备结构上的可执行条件。§II-D 的外部攻击者可观察公开 Skill 并控制被读取的第三方内容，不能操纵用户输入、直接发布恶意 Skill 或修改 Agent 框架。图 3 明确排除修改 Skill。由此可见，论文的实验问题与同一 Skill 更新前后的归因不同。[§II、图 2–3](https://arxiv.org/html/2610.32155v1#S2)

## §III-A/B　SCS 的定义、提取与粒度

SCS 的输入单位是一个 Skill。§III-B 通过六类信息给出结构性定义，没有给 SCS 单独的编号公式、形式元组或可直接反序列化的 schema。图 4 把 SCS 输出表示为建图所需的能力事实；式 (1) 在下一节才定义跨 Skill 边的资格。[§III-B、图 4](https://arxiv.org/html/2610.32155v1#S3.SS2)

| §III-B 的六类信息 | 原文记录的内容与用途 |
|---|---|
| 输入／输出端口（合计一类） | 按端口记录数据类型、敏感性、信任来源、暴露范围、可消费性 |
| 安全效果 | 处理数据产生的副作用，并描述敏感性是否保留、是否跨越信任边界、是否需要授权 |
| 操作 | Skill 提供的动作及参数，用于判断 Agent 能否提供输入。输入可控性与动作授权分开判断 |
| 上下文暴露 | Agent 上下文、工作区、外部和持久状态等可见范围，用于判断输出可观察性 |
| 信任边界 | 本地、第三方、互联网与持久状态之间的跨域关系 |
| 证据 | 每项主张的来源文件、片段、提取方法和置信分值 |

提取可追溯到三种明确写出的操作：解析 YAML frontmatter 取得结构化声明，在自然语言描述中做启发式匹配，静态扫描脚本以识别代码行为。§II-A 与图 4 把说明、脚本、模板和资源纳入 Skill 材料。§III-B 没有列出各字段的解析键、匹配规则、脚本语言覆盖、证据冲突解决方式或分值计算方法。原文一句话列出三种操作，却提及四类覆盖内容，最后一项是规则难以捕获的语义属性。仅凭这句话无法还原第四种提取器，或指定某个 LLM、提示词及调用顺序。[§II-A](https://arxiv.org/html/2610.32155v1#S2.SS1) · [§III-B、图 4](https://arxiv.org/html/2610.32155v1#S3.SS2)

类型需按维度阅读。URL 和 Text 是式 (1) 讨论的有向兼容示例；表 I 还举出 Code 和 Command。Private、Secret、DerivedSensitive 属于敏感性，Internet、ThirdParty 描述来源，LocalOnly 描述可见性限制。向外发送、执行任务、写入持久状态是效果或策略关注的终点。表 I 用 DE、IPI、CEP、FP 表示四种策略。把这些名称并成一个“能力类型”枚举会丢失它们的不同语义。论文给出了上述角色及示例，完整兼容表和机器类型字典仍待取得。[§III-B/C、式 (1)、表 I](https://arxiv.org/pdf/2610.32155v1#page=4)

## §III-C　端口级 SCFG 与两种关系

原文定义图 G=(V,E)。V 包括 Skill、输入端口、输出端口、效果、操作、上下文节点与信任边界节点。内部关系明列读取、产生、转换、暴露、清洗和跨边界（reads、produces、transforms、exposes、sanitizes、crosses-boundary）。证据在 §III-B 属于主张的依据，§III-C 的节点清单没有把它另列为节点类型。[§III-C、图 4](https://arxiv.org/html/2610.32155v1#S3.SS3)

算法 1 的输入是 SCS 集合、类型兼容表与每个输出端口的边数上限 b。第 3–5 行先加入各 Skill 内部结构。第 7–14 行才按输入类型索引，在不同 Skill 之间筛选输出端口 o 与输入端口 i。式 (1) 要求类型兼容、输出对 Agent 可观察、输入可由 Agent 提供，且两端各有相应证据。这是结构性通道条件；实际保留边还受第 12 行的优先级及 b 限制。内部的转换或清洗无需引入第二个 Skill，也不能由上述四个跨 Skill 谓词自动推出。[§III-C、式 (1)、算法 1](https://arxiv.org/html/2610.32155v1#S3.SS3)

## §IV　实验回答什么，如何隔离

§IV-A 采用 2026-05-18 的公开市场快照；§IV-B/C 的表 II/III 比较组合链在 Agent 与模型上的运行结果和对照基线。§IV-D 表 IV 的计时明确排除 SCS 提取、LLM 审计和序列化；§IV-E 表 V 消融的是 Handoff 的可观察性及可控性；§IV-F 图 5 与负对照考察具体组合。上述实验没有提供单 Skill 内部边的标注集、边级准确率或修改定位结果。伦理说明记载原实验在隔离的本地网络模拟两方，未接触真实用户或第三方服务，并向平台披露。P01 仅读取论文，未取得或运行其样本。[§IV-A–F、表 II–V、图 5](https://arxiv.org/html/2610.32155v1#S4)

## §V–VIII　局限及项目解释

§V 指出 Agent 决策具有随机性，每个组合的重复次数受限，市场快照也不能代表私有、删除或历史版本。§VI-A 把检测边界归于策略覆盖、仅建模 Agent 介导的通道，以及真实可利用链全集不可观察。共享路径、环境变量或外部状态形成的隐式通道可能绕开 DER。§VI-B 讨论节点、边与运行框架上的防护；§VII 回顾包括程序依赖图在内的相关研究；§VIII 总结组合风险。引用相关工作的程序表示不足以把其粒度归给 KnotScryer。未观察到路径、证据不足以及行为具有恶意意图，是三个不同的研究判断。[§V](https://arxiv.org/html/2610.32155v1#S5) · [§VI–VIII](https://arxiv.org/html/2610.32155v1#S6)
