# P13 单版本有限轨迹策略求值设计

依据 P11 algorithm_spec §4 和 threat_model「从安全属性到策略」。Schneider 的有限坏前缀给出监视器形式，KnotScryer §III-D/E 区分可能效果与验证。以下两条规则由 DCFA 威胁模型给出。

固定观察键（策略、主体、资源、效果）及调用上下文（用途、调用实例）。策略语言为封闭的两个有类型规则，谓词采用三值合取。保密规则要求 send、私有来源、到达效果时敏感性仍保留、目标在边界外、无有效放行。完整性规则要求 write、不可信来源通过值或可信控制绑定影响受保护目标、无有效授权。已知不同效果使规则不适用；其他排除条件在适用范围内参与求值。

输入为 P04 图、P05 索引、绑定图摘要的可信分析者契约。契约针对单键单上下文列举可能前缀（源节点、按顺序排列的边、效果节点）。path 由求值器沿图重放；operand 和 result_to_operand 可承载程序数据，最后一条边的实参用途及全程对象传递由该前缀的可信绑定证书限定。独立控制依赖与跨模态桥接当前缺少图边，须保持开放覆盖。feasible 是该完整前缀在固定上下文中的可行性事实，包含所有执行守卫。无证书的 may 路径保持未知。所有语义事实来自独立可信环境，禁止从待测文本导入契约。每个前缀有独立来源说明。授权精确匹配主体、动作、资源、用途、调用和数据来源节点，显式否定与开放环境无记录有不同结果。认证覆盖声明须涵盖该键全部可行行为和上游缺口。

输出为状态、上下文的下上界成员标志、证据路径与缺口。若存在完整坏前缀则属于下界；无未决前缀并有闭包证书则排除出上界。每条有限证书顺序重放，循环允许重复节点，时间与提交的路径总长度、图索引及授权记录数相关。接口拒绝错图、断链、无效事实与授权冲突。不执行程序。

预定义独立预期：无授权的私有越界发送及不可信受保护写入均违规；授权、非敏感来源、可信降密或不可行守卫在闭包下安全；未知授权、缺封闭覆盖、无完整绑定或可行性证书均未知；无关用途授权不匹配；效果种类不匹配独立返回不适用；结构归属不可作来源传递；旧新版本输入不在接口中。

## 二审前修复设计

N01：对固定资源和调用，protected 是可信环境对该资源的分类。若已提交前缀一致证实该资源不受保护，完整性坏事件可排除；若资源可能受保护，普通前缀清单不能封闭未建模的控制影响。此时保留上界并说明原因，即使所有已列值路径均被排除。该规则也适用于空清单。相互矛盾的资源分类拒绝求值。保密规则继续依赖原设计的可信范围证书。S01：先校验授权和前缀结构，再对适用动作归类。S02：保持开放授权表。S03：在改实现前固定吸收、精确来源、混合结果与输出隔离测试；另用有限布尔补全求上下界作为独立对照。
