# P11 研究问题：同一 Skill 更新是否改变了可支持的违规行为

**设计状态：待人工审核。** 研究单位是同一发布实体的两份不可变快照。P11 提出供后续证伪的定义，没有训练、调参或外部评价。三份文档分别规定问题、信任假设与比较过程。[威胁模型](threat_model.md) · [算法规范](algorithm_spec.md)

## 输入、目标与非目标

给定 $(V_1,V_2,E,Π)$，其中 E 是固定运行与分析契约，Π 是独立于两个版本的策略集。任务是找出哪些策略、资源、效果和上下文中的违规见证可能新增、保持或消失，并给出版本内证据、比较成立的前提及相关修改。输入包括说明、程序和调用方提供的可信声明。仅考虑一次单 Skill 调用内可解释的行为；不把两个 Skill 的输出与输入接起来。版本关系由来源记录或调用方提供；无法确定为同一 Skill 时停止比较。

输出是一组 $(策略,观察键,上下文区域,旧状态,新状态,变化,两侧见证,修改关联,未知原因)$。一条更新可以同时新增一类违规、缓解另一类违规。没有加权总分，也不从提交者身份、代码规模、告警数量或单次未触发推断意图。

**最小区分例。** 同一声明工具在两版都可能把合成 private 数据交给外部端点。旧版仅在有有效授权时允许该操作，新版移除这个已证实生效的门。程序域对可能完全相同；在“未授权”上下文，策略状态却可能变化。反过来，新增一个只接收 public 数据的外部端点可以产生新的域对而无保密违规。两个判断分别依赖门的语义和数据分类；缺其中一项时允许未知。这是研究动机，不是对真实样本的测量。

## 可证伪的研究主张

1. 若以策略可见的角色对齐、另比较保护条件，在证实旧版对该键没有违规上下文、新版删门后存在违规上下文的算例中，整体标签为「引入」，未授权上下文进入确定新增区域。若旧版已有违规且新版严格覆盖旧集合，才称「范围扩大」。若系统只能看到两个不相关的增删实体，此主张在该用例上失败。
2. 若强制前后使用相同的来源、授权及资源契约，纯改名不应制造变化。若多个匹配同样有据但给出不一致归属，则应返回歧义。
3. 若差异位置只与见证相邻，替换该修改后模型仍能产生同一变化，则不能把它报告为该变化的必要解释。两条独立见证可能没有共同的必要修改。

候选研究贡献是**在部分证据下，将跨版本对应的不确定性传递到策略差分及修改解释**。SCS、域可达、策略自动机和集合差分别来自已有研究，组合使用本身不证明新颖性。后续应比较冻结基线、仅程序、仅文本、无条件状态、强制唯一对应等消融；比较相同输入与覆盖，分别报告正确变化、错误变化、未知及证据可重放性。若预先定义的区分例无法区分这些方法，贡献假设须收缩。上述实验留待批准，不构成性能结论。
