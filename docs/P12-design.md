# P12 有限契约内的语义能力对齐

依据 P11 §3。输入为同一 Skill、同一可信环境 E 的两个 P04 图、各自 P05 索引及分析方提供的有限能力契约。出现位置只在本版使用。研究子集为 operation/effect 实体，允许把有完整组合契约的若干出现预先聚成一个逻辑单元。开放覆盖或无组合证据时允许弃判。此输入选择用于区分“代码里出现动作”和“已知该动作的完整语义”。

身份对应取决于同一逻辑职责的连续性。角色键依次为主体、动作族、有向参数接口、资源角色、效果类别，采用 E 的规范符号。连续性证明可为稳定绑定，或 E 明示角色在封闭范围内唯一且持续；后者必须排除所有竞争者。结构约束只用 E 指定为身份不变量的有向关系与已绑定邻居，普通上下文变化可修改行为，不能仅据此排除对应。分拆、合并须给出明示聚合成员与整体契约，不推断任意子集的组合。完整等价比较规定投影下的有限观察关系 (上下文, 输入, 输出, 安全剖面)；安全等价仅比较其 (上下文, 安全剖面) 投影。安全剖面是 E 定义的联合取值，涵盖来源、敏感性、目标边界、授权及执行约束。每一行代表整体联合观察，不逐列独立拼接；缺表表示未知，空表表示已证无观察。

伪代码：核对环境、版本、图和证据索引 → 按契约构造互不重叠单元，登记未绑定出现 → 两两剔除已证角色、稳定绑定或结构冲突，保留未知竞争者 → 固定有唯一稳定绑定的对应，剔除其占用项 → 仅在封闭覆盖、角色持续契约、双向唯一且角色完全已知时确认其余对应 → 对保留的候选不强制选择 → 两侧封闭且无可能对应时确认增删 → 对每个已对齐单元比较有限观察表及安全投影，输出分别的判定和差异证据。可信唯一绑定重复或约束矛盾作为冲突；不做最大匹配、文本打分或阈值拟合。置信度用证据等级表示，无概率含义。

事前性质：改名/移动和受契约支持的改写保持身份与两类等价；相同身份的非安全输出变化仅改变完整语义；删授权门改变安全语义；重复角色保持歧义，顺序无关；单侧缺覆盖不报增删；显式组合拆分与反向合并分别报告；无契约文本近似不能证明对应。使用合成数据与真实前置接口。最坏枚举 n×m 个单元对，另计结构与契约处理，具体复杂度和局限随实现报告。

## 独立审查修复设计

N02 在返回边界分别复制两侧证据。S02 保留可信契约接口，并允许两侧共同提供 neighbor_bindings 字典，将版本内节点 ID 映到契约语义名。启用后，槽声明必须与实际边对端的登记值一致且对端有已核验原始见证，否则拒绝该契约。节点编号仅用于版本内查证。登记表本身仍是人工假设。S03 在执行前规定预期：唯一候选缺乏持续性契约时弃判；未绑定竞争者阻止唯一配对；只改变输入列会改变完整观察但保持安全投影。N01 等待授权归档。
