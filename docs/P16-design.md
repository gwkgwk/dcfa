# P16 完整集成设计及验收预期

研究对象是固定环境中同一 Skill 两份只读快照。调用 analyze_update(old_path,new_path,config)。config 是可信调用方提供的 JSON 对象，与待测目录分开保存。configuration 指定共同工具、精度和预算的版本；before/after 分别保存 P12 contract，可选 P04 bindings 与可信 binding_file。queries 列出预先声明的 id、key、contexts，以及 before/after 两侧 members 和 contracts（P13 契约序列）。分析者负责将契约绑定到对应图摘要；缺报告保持缺测。空查询只产生表示与对齐，并标记未评价。单元可按 P12 对应、已确认增删或未决传入。一次调用返回所有查询，保留各自的差分与关联。

## 伪代码（P11 §1–5）

1. 对每侧用 P03 受限扫描获取内存字节、SCS 与诊断；P04 从 SCS 和可信绑定建图，P05 重放原件建索引。核对字节清单与索引摘要。文件读取、解析或快照一致性失败则保留侧别和失败证据，停止比较。
2. 用有序的相对路径及逐文件 SHA-256 计算完整字节清单摘要。令 M=P12.align(旧表示,新表示)，保持契约条件下的对应、增删和未知。
3. 对每个预定义策略键 k 和上下文域 C，两侧分别调用 P13.evaluate 重放提交的前缀，获得 L、U、见证与缺口。P14.compare 在 M 和固定配置下计算新增 [L₂∖U₁,U₂∖L₁]、缓解的反向界及共同区域。对容许的整键解释一致时才给唯一标签。
4. 对该差分调用 P15.attribute，用 P05 原件、两侧文件字节及 M 重放每个方向的编辑交集、位置证据、有限语义前提和不确定性。保留所有键的记录，互不抵消。
5. 输出快照摘要、SCS、图、证据索引、对齐、差分、关联及配置标识。总流程成功只表示完成指定查询。可信契约非法时异常退出，无安全结论。

预期先于执行固定：相同快照未知自比较保持且无新增上界；改名和同义指令在可信角色绑定与精确投影下保持；一个上下文持续违规、另一个新增时为加剧，交换两侧为缓解；未知到违规不能确认为引入；已绑定常量变化的证据回到两版真实行；纯指令与程序都走同一入口，混合快照按真实图边分别重放，缺桥接证据不得产生跨模态路径。

复杂度为两侧提取、建图、索引各一次，加 O(n₁n₂) 单元候选比较（另计角色/槽检查），各查询逐报告累加 P13 图校验与前缀重放、P14 至多八状态的有限域比较及 P15 证据扫描。P15 每个查询重算行 diff，SequenceMatcher 单文件最坏二次时间；原件重放与见证复制的费用依赖原文件长度及重复引用数。空间包含两侧图、索引、文件字节与所有查询输出。

## 审查修复设计

S02：每侧 problems 是面向调用方的失败摘要。它与同一报告内的原始 SCS 诊断应可分别修改；在发布摘要时复制诊断记录。整份报告一次 deepcopy 会保留对象内部的共享引用，无法单独解决这项要求。S01：用预先给定的授权集合验证两个键的相反方向、同字节授权变化、位移后的两侧精确行与跨模态隔离；对错误契约测试拒绝。N01 只更新规范的进度段。N02 留待授权归档。
